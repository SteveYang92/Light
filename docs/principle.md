# Light项目的设计原则
## 原则一：模块化设计
不将功能堆在一个大的package里，而将独立的功能以模块的形式组织，每个模块一个包，这样：
- 产品层面
    - 用户可按需要安装功能包，不用被迫安装用不到的组件（例如，用户的软件栈只缺少某一特定功能，这个功能我们做了）
    - 开发者可对模块可进行深度且聚焦的优化，形成竞争力（例如，围绕谋一功能，不断打磨）

- 工程层面
    - 可以独立的开发、测试及发布

## 原则二：Agent First设计
- 采用Mono Repo，所有模块代码在一个仓库下，Agent不用切仓库、切工作目录，所有模块代码直接访问；
- 软件的运行日志、运行状态信息、中间产物等都会持久化，发生问题事后可分析
- 软件运行的最终制品产物，既有For Human的，也有For Agent的
- 软件主体和软件测试是一体化设计，相互对抗、共同进化（设计和实现一个功能方案，就要设计和实现一个测试方案，这是功能自迭代的基础）


## 原则三：面向用户的设计
- 我们的目标不是写多少代码，而是交付对用户有价值的功能
    - 从用户角度出发，思考功能设计（例如，设计一个字幕格式化框架，首先要去想，字幕怎么看舒服，一行100个字，肯定不舒服，要拆分、要断句、要做行平衡等）
- 我们写测试，不是为了覆盖率，写测试是为了保证功能质量（从这个角度，我们就知道代码需要测试，只写单测肯定不够，我们需要集成测试，需要E2E，需要提前知道这个功能真正实际运行起来是对是错）

## 原则四：优雅简洁
- 有清晰的用途和目标，清楚的“布线”，无论是产品功能还是代码都如此
- 不做过度设计，也不能毫无设计

## 原则五：长期主义
- 不做临时功能、临时Patch，不为细枝末节，损坏全局
- 每个设计都要考虑，这个设计能为未来代理什么持续性收益，还是埋下持续劣化的种子
- 宁可不做，也不错做

## 原则六：沉淀和自迭代
- 沉淀知识、经验
- 积累工程方法，让功能可自迭代
